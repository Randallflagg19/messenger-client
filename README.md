# Messenger Client

Тестовое задание на позицию Frontend React Developer: клиент для обмена текстовыми сообщениями в Telegram через GREEN-API. Telegram выбран из разрешённых в задании мессенджеров. Светлый интерфейс использует структуру MAX: список чатов, область переписки и поле ввода сообщения.

Приложение реализует основной сценарий задания: пользователь вводит данные инстанса, создаёт чат по номеру телефона, отправляет сообщение и получает ответ собеседника без обновления страницы.

## Быстрый запуск

Требуются **Node.js 22.22+** и npm.

```bash
npm ci
npm run dev
```

Откройте адрес, который Vite выведет в терминале (обычно `http://localhost:5173`).

Для знакомства с интерфейсом без учётных данных нажмите **«Открыть демо»**. В этом режиме доступны пример переписки, создание чатов и локальная отправка сообщений. Запросы к GREEN-API не выполняются.

## Подключение Telegram

Для реального обмена сообщениями нужен авторизованный Telegram-инстанс в личном кабинете GREEN-API и второй Telegram-аккаунт для проверки ответа.

1. В кабинете откройте инстанс и убедитесь, что его статус — **«Авторизован»**.
2. Сверьте `apiUrl` инстанса с `apiUrl` в [`src/config.ts`](src/config.ts). В проекте указан `https://4100.api.green-api.com`; если адрес вашего инстанса отличается, замените его в конфигурации.
3. Нажмите **«Изменить»** и в разделе **«Уведомления»**:
   - оставьте поле **«Адрес отправки уведомлений (URL)»** пустым;
   - включите **«Получать уведомления о входящих сообщениях и файлах»**;
   - нажмите **«Сохранить изменения»**.
4. В приложении введите `idInstance` и `apiTokenInstance`, затем нажмите **«Подключиться»**.

Приложение проверит состояние через `GetStateInstance` и откроет рабочий экран только при ответе `authorized`. Данные инстанса вводятся через форму: добавлять токен в исходный код или `.env` не требуется.

## Как проверить основной сценарий

1. Подключитесь к инстансу и нажмите **«Новый чат»**.
2. Введите номер второго аккаунта с кодом страны. Российский номер можно ввести через `8` или `+7`: он будет приведён к формату `+7`.
3. Создайте чат. Приложение вызовет `CheckAccount`, чтобы получить Telegram `chatId` для указанного номера.
4. Отправьте текст и убедитесь, что он появился у получателя в Telegram.
5. Ответьте с аккаунта получателя. Ответ должен автоматически появиться в приложении, а последнее сообщение — в списке чатов.

Для проверки откройте одну вкладку приложения: несколько клиентов одного инстанса будут читать общую очередь уведомлений.

Если аккаунт не находится по номеру, причиной могут быть настройки приватности или ограничения сервиса. Если ответы не появляются, проверьте настройку входящих уведомлений и сообщение о состоянии получения в верхней части приложения.

## Что реализовано

- Подключение с проверкой состояния инстанса и выход из сессии.
- Создание личного чата по номеру, выбор чата и отдельный черновик для каждой переписки.
- Отправка текста через `SendMessage`, включая переносы строк; ограничение — 4096 символов.
- Получение обычного текста и текста со ссылками через `ReceiveNotification`.
- Подтверждение обработанного уведомления через `DeleteNotification` и защита от повторного добавления сообщения.
- Автоматическое появление чата при входящем сообщении от нового собеседника.
- Обработка ошибок, таймаутов и временных сбоев получения.
- Адаптивный интерфейс, автоматическое изменение высоты поля ввода и сохранение позиции при чтении старых сообщений.

Надпись **«Принято в очередь»** означает, что GREEN-API вернул идентификатор отправленного сообщения. Она не означает доставку или прочтение получателем.

## Устройство проекта

**React 19, TypeScript, Vite, CSS Modules.** Состояние хранится средствами React; отдельный сервер, база данных и глобальный менеджер состояния для этого объёма задачи не используются.

| Файл или каталог | Назначение |
| --- | --- |
| `src/App.tsx` | Переключение между формой подключения, рабочей сессией и демо |
| `src/components/` | Форма подключения, список чатов, переписка, ввод сообщения и диалог нового чата |
| `src/components/Messenger.tsx` | Состояние чатов, сообщений и черновиков; связь интерфейса с API |
| `src/api/greenApi.ts` | HTTP-запросы, проверка ответов, таймауты и сообщения об ошибках |
| `src/api/notifications.ts` | Разбор входящего текста и последовательная обработка очереди |
| `src/hooks/useNotifications.ts` | Запуск получения на время сессии и отмена запросов при выходе |
| `src/types.ts`, `src/utils.ts` | Модели чата и сообщения, обработка номера и вспомогательные функции |
| `src/mockData.ts` | Данные для деморежима |
| `tests/` | Тесты API и обработки уведомлений с подставными ответами |

Получение организовано последовательно: **запрос уведомления → обработка → подтверждение → следующий запрос**. При временной ошибке выполняется повтор с увеличением паузы. Ошибка подтверждения приводит к повтору подтверждения, а не повторному добавлению сообщения. Некорректное текстовое уведомление остаётся в очереди, получение останавливается с сообщением об ошибке.

На время отправки поле текущего чата доступно только для чтения. После успешного ответа оно очищается, при ошибке текст сохраняется и редактирование снова доступно.

Отправка автоматически не повторяется: при сетевом сбое запрос мог уже дойти до сервиса. Черновик сохраняется, а интерфейс предлагает проверить Telegram перед повторной отправкой.

## Границы реализации

- Поддерживаются личные текстовые переписки. Файлы, изображения, группы, редактирование, удаление и статусы доставки не реализованы. Уведомления вне этого объёма пропускаются с подтверждением, чтобы не блокировать очередь.
- История Telegram не загружается. Приложение показывает сообщения текущей сессии, включая поступившие из очереди уведомлений.
- Учётные данные, чаты, сообщения и черновики хранятся только в памяти приложения. Выход или перезагрузка очищают их; `localStorage` и `sessionStorage` не используются.
- Запросы выполняются из браузера напрямую в GREEN-API. Токен необходим для этих запросов и доступен владельцу браузера в инструментах разработчика; приложение не выводит его в сообщения об ошибках.
- Реализована интеграция с Telegram. Одной смены названия и адреса в конфигурации недостаточно для поддержки другого мессенджера: потребуется проверить его методы и форматы ответов.

## Проверки и сборка

```bash
# Статический анализ
npm run lint

# Проверка TypeScript и production-сборка в dist/
npm run build

# Локальный просмотр production-сборки
npm run preview

# Тесты без токена и обращений к реальному инстансу
npm test
```

Тесты проверяют авторизацию, поиск аккаунта, отправку, некорректные ответы, таймауты, разбор входящих сообщений, порядок обработки очереди, повтор подтверждения и отмену получения при выходе. Реальная отправка и получение текста также проверены вручную между двумя Telegram-аккаунтами.

Браузерные проверки интерфейса (первый запуск требует установки Chromium):

```bash
npx playwright install chromium --only-shell
npm run test:e2e
```

Playwright запускает отдельный локальный сервер на порту 5175 и перехватывает запросы GREEN-API. Проверяются переключение чатов во время отправки, блокировка поля на время отправки, сохранение черновика при ошибке, отмена получения при выходе и прокрутка переписки на узком экране. Реальный токен не требуется.
